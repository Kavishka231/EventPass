# Testing

From `backend/`, run `mvn spotless:check verify` with Java 21. Unit tests cover financial idempotency, JWT validation, refresh-token families, administrator lifecycle rules, HTTP security configuration, notification delivery transitions and ownership, the exact event envelope, and outbox retry behavior. Testcontainers applies every Flyway migration to PostgreSQL and verifies domain races, event cancellation, competing publishers, notification idempotency, concurrent last-admin protection, and the HTTP authorization matrix for roles, ownership, suspended accounts, invalid/expired JWTs, and refresh-token reuse. A dedicated PostgreSQL/Redis/Kafka Testcontainers test executes a successful booking transaction through durable outbox persistence, the real outbox publisher and Kafka broker, the real notification listener, and persisted customer notification; it also verifies duplicate-delivery idempotency and the configured retry path into the real dead-letter topic. MockMvc contract tests additionally assert booking success payloads, validation failures, authentication failures, idempotency conflicts, bounded pagination, and the complete standardized error envelope through the real security and persistence stack. Authentication integration coverage exercises registration, duplicate registration, login, inactive-account enforcement, refresh rotation, logout, and replay-driven token-family revocation through the HTTP API. Event and inventory integration coverage verifies administrator venue/seat creation, capacity enforcement, organizer ownership, inventory-required publication, server-persisted pricing, seat blocking, public inventory, and post-publication locking. Booking lifecycle coverage verifies successful payment and ticket generation, durable payment failure, expiration events and seat release, cancellation/refund, resale with a replacement ticket, and idempotent replay without duplicate bookings, payments, or tickets. The end-to-end MockMvc journey registers and logs in a customer, browses a uniquely filtered published event, selects its available seat, completes payment-backed booking, and retrieves the resulting active digital ticket. Docker must be running for infrastructure tests. Testcontainers 1.21.4 is required for current Docker Engine API compatibility.

Load and contention testing uses the k6 suite documented in [`performance/k6/README.md`](performance/k6/README.md). It requires isolated production-like infrastructure, dedicated customer credentials, and a published event with resettable inventory. Preserve its JSON summary and correlate client throughput, latency, and errors with server business metrics and infrastructure saturation. Load-test execution is deliberately separate from pull-request CI because it consumes real inventory and needs controlled capacity. No performance figures are claimed until these scenarios are executed in a representative environment.
